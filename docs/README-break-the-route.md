# BREAK THE ROUTE（仮称）

警察と犯人の3Dカーチェイス（2026-10-26 にレースから作り変えた）。運河の街（湾岸シティ）で、犯人は逃げ切るか隠れ家へ、警察はぶつけて止めて逮捕する。柵・街灯・バリケード・一般車は吹き飛ばせる。手本は GTA の手配度とヘリ、Need for Speed の逮捕ゲージ（調査メモ `docs/asphalt8-research.md` は前のレース版のもの）。

- 遊ぶ: https://tom3games.github.io/break-the-route/ （PC もスマホも。オフラインで「犯人で逃げる」か「警察で捕まえる」。CPU の警察は1〜6台）
- 友達とオンライン: このリポジトリのサーバーを起動して、そのURLを開く（下の「オンライン対戦の遊び方」）

タイトルは `public/shared/config.js` の `GAME.title` で変えられる（画面のロゴは `public/index.html`）。

## 遊び方（勝ち負け）

| | 勝ち | 負け |
|---|---|---|
| 犯人 | 制限時間（3分）を逃げ切る。または 90 秒後に開く隠れ家（毎回場所が変わる。緑の光の柱）に、警察に見られずに（40m 以内に警察がいない）入る | 逮捕される |
| 警察 | 犯人を逮捕する | 逃げ切られる |

- 逮捕ゲージ: 犯人のそば（10m）に警察がいて、犯人が遅いとたまり、約2秒で逮捕。「遅い」の基準は、警察1台なら時速40km未満、2台以上に囲まれていれば時速72km未満、警察がぴったりくっついている（5.5m 以内）なら時速90km未満。離れるとゆっくり減る
- 犯人の車が大破したとき、45m 以内に警察がいれば逮捕。警察に体当たりされた犯人は大きく失速してよろける
- 手配度（星1〜5）: 35秒ごとと、犯人が警察の車を大破させるたびに上がる。上がるほど警察の CPU が速く、無線（目撃情報）が増え、星3つからヘリが犯人を照らす
- 警察の地図には、犯人が近い（130m）とき・無線の直後・ヘリが照らしているときだけ赤い点が出る。見失うと輪の印が最後の目撃。車の上の矢印は、犯人（警察）か隠れ家（犯人）へ、道なりの次の交差点を指す
- 犯人には近く（320m）の警察が地図に見える。警察は隠れ家の場所を知らない（CPU は警察が3台以上いると1台が隠れ家に張り込む）
- 犯人に3秒の先行（警察はスタートで3秒待つ）
- パトカーは壊せる（2026-10-26 本人「警察の車の耐久ちょっと低く、クラッシュさせられるように。リスポーンまで少し時間」）: 警察車の耐久は車の値の 0.75 倍（`CHASE.copDurability`）。犯人に突っ込まれた側のときだけ損傷が 20 倍（`copRamTaken`）。全力（時速160km）で後ろから当てて3回、横から（時速120km）で4回で大破（前は8回当てても無傷に近かった）。警察が犯人に当てる側の自損は今のまま（6回当てて車体86%）。大破したパトカーはその場で6.5秒燃えて残り（`copWreckSec`、前は1.3秒でその場復帰）、犯人から160〜300m離れた交差点に戻る。パトカーを潰すと手配度が1上がり、犯人にテイクダウンとニトロ35%。オンラインでは人の警察車の大破もサーバーが数える
- CPU 同士の勝ち負け（警察3台、3通りの種で各14回 = 42回）: 逮捕16・時間切れ16・隠れ家10（逮捕38%）。離された CPU 警察の追い上げを 0.2→0.35 に上げて釣り合わせた（`copCatch`）
- 車は丈夫（2026-10-26 本人「耐久値上げて」）: 壁の傷みは前の約3分の1（`DAMAGE.wallBase` 0.0032→0.0011、傷まない速さ 7→9m/s、車同士 0.35→0.25、ニトロ中の倍率 1.35→1.2）。時速100kmで壁に当てても車体の傷みは15%未満
- ドリフト（2026-10-26 本人「ドリフトの時滑りすぎ」）: 横のグリップ ドリフトボタン 0.16→0.42 倍・曲がりながらブレーキ 0.3→0.55 倍、横滑り角の上限 32 度を新設、ドリフト中の曲がりやすさ 1.45→1.9、ハンドルを戻したとき向きを戻す速さ 2.2→4（`PHYS`）。時速108kmから90度曲がるのに ドリフトボタン 72m→53m・ブレーキ 45m→43m、最大の横滑り角 57度→31度・44度→25度、抜けてから真っすぐに戻るまで 0.30秒→0.20秒（`node tools/drift-test.mjs`）
- カメラ（2026-10-26 本人「カメラの距離を近く」）: 近い視点 後ろ3.25m・高さ1.15m → 2.85m・1.05m、引き 6.0/2.0 → 5.2/1.8。前は速いほど車に置いていかれて時速160kmで実際は約8m後ろだったので、位置は車にぴったり付け、向きだけをなめらかに追うようにした（速さで最大1.2m引く）。縦画面の上乗せ 0.4/0.45 → 0.3/0.35、縦画面の視野を少し狭く（最大90→84度）。速さで視野が最大14度広がり、ニトロ中はさらに8度
- 爽快感: 強く当てた瞬間の一瞬の停止（ヒットストップ）・カメラの揺れ・火花とガラス片・ガラスの割れる音、パトカーを潰した瞬間とジャンプの瞬間の短いスロー、「テイクダウン」「ニアミス」「ビッグエア」の大きな文字とコンボ（4秒以内に続くと x2・x3、ニトロの回復が1.5倍・2倍）、ニトロ中の流れる線と小刻みな揺れ、速さで上がるエンジン音、逮捕の赤青の光・逃げ切りの金色の紙吹雪とスロー。スローとヒットストップはオフラインだけ（オンラインは全員の時計が同じなので見た目だけ）
- 一般車は軽い（2026-10-26 本人「普通に走ってる車が重すぎる」）: 質量 1.3→0.35。ゆっくり押しても横へどき、速く当てると吹き飛ぶ。台数は約270台→166台、見た目を割り当てる台数はスマホ 22→12・PC 44→26、描く距離は 300m→170m（スマホ）/220m（PC）。遠くの車は高さの計算を省く

- 修理工場（街に4か所。青い「REPAIR」の屋根、地図の青い四角）: 中で3秒止まる（時速11km未満）と全回復（ニトロも満タン）。使ったあと40秒はその車は使えない。犯人は40m以内に警察がいると直せない（見張られている工場は使えない）。犯人が直すと手配度が1下がり、警察は見失う（目撃情報が消え、次の無線まで8秒以上あく）。CPU の犯人は車体が45%を切ると、警察のいない工場へ寄る
- 警察ヘリのランチャー（手配度3から）: 犯人の上空を追い、犯人が「そのまま走ったら1.5秒後に来る場所」に赤い円（半径7m）と照準を出し、1.8秒後に着弾（最後の0.6秒はミサイルが飛んでくる）。曲がる・止まる・急ぐで避けられる。発射の間隔は手配度3で6秒、4で4.5秒、5で3.5秒。当たると吹き飛んで車体が最大30%（耐久1の車。円の端ほど弱い）・エンジン15%・タイヤ12%傷むが、車体は8%より下がらない（ミサイルだけでは大破しない）。警察役のときは味方のヘリとして犯人を撃つ。ローター音・ロックオンの警告音・爆発音つき

- 拳銃（手配度2から、2026-10-27 追加）: CPU のパトカーが、60m 以内で建物の陰でない犯人を撃つ。間隔は1台あたり手配度2で約1.5秒、5で約0.75秒。近くて遅いほど当たり（最大6割、最低15%）、1発で車体1.5%（耐久1の車）。弾だけでは車体は12%より下がらない。弾道の光・銃口の光・発砲音・被弾の跳ね音つき。オンラインはサーバーが撃ち、当たった犯人の画面が傷みを入れる

- スパイクベルト（手配度4から、2026-10-27 追加）: 犯人が道なりにそのまま走ったら約2.6秒後に来る所（最低55m先）に、道の幅の6割を塞いで敷く（残りの片側を通れば避けられる）。間隔は手配度4で12秒、5で8秒、同時に2本まで、16秒で消える。黄色く光る帯・両端のコーン・地図の黄色い線。踏むとパンク（タイヤがほぼ効かず最高速72%）、修理工場か大破からの復帰で直る。警察は踏んでもパンクしない

- 警察の数と応援（2026-10-27 追加）: オフラインで最初に選べる警察は1〜10台（初期値5）。手配度が上がるたびに、犯人から離れた交差点に応援のパトカーが足される（手配度3で+1、4で+2、5で+4、最大14台）。オンラインは応援なし

調整値は `public/shared/config.js` の `CHASE`（時間・逮捕・手配度・無線・ヘリ・ランチャー・拳銃・スパイクベルト・修理工場・スタート距離）。

## 技術選定

**Three.js（ブラウザ）＋ Node.js（WebSocket サーバー）。物理は自前のアーケード物理。** Godot 4 を第一候補として比べ、次の理由でこちらにした。

1. **友達を呼ぶ手間がいちばん少ない。** 招待リンクを開けば遊べる。Godot は配布ファイルのダウンロードとインストール（Mac は署名の警告）が要る。Godot も Web に書き出せるが、オンラインには結局 WebSocket サーバーを別に用意することになり、ゲームの判定をサーバーと共有しにくい
2. **同じ物理をサーバーで動かせる。** 車の挙動・コース・レース判定を three.js に依存しない JavaScript（`public/shared/`）にまとめ、ブラウザとサーバーの両方が同じファイルを読む。サーバーはこれで CPU 車を走らせ、ゲート通過とゴールを判定する
3. **検証を自動で回せる。** 描画なしで物理を回すテスト、実ブラウザ2つをつないで最後まで遊ぶテスト、全画面のスクショをこの環境で動かせる。この Mac には Godot が入っておらず、実画面を撮って直す流れを作れなかった
4. **物理エンジンを使わない理由。** 車の気持ちよさ（ドリフト・大ジャンプ・着地）は汎用の剛体物理だと調整が難しく、ネット同期では決定的でない物理が不整合の元になる。4輪の接地点で姿勢を決め、速度を路面に沿わせる単純な計算にしたので、数値を変えるだけで性格を調整できる

捨てた案: Godot 4（上記1と3）、Unity（同じく配布とライセンス、重さ）、Firebase 等の外部サービス（有料化と料金の読めなさ、必須にしない方針）。

### 車の挙動を変える

`public/shared/config.js` の `CARS`（最高速・加速・グリップ・ハンドル・耐久・空中制御）、`PHYS`（重力・着地の許容速度）、`DAMAGE`（ダメージ係数）、`DESTRUCT`（壊れる勢い・失う速度・硬さ）。改造は `UPGRADES` の `apply` で何を上げて何を下げるかを書く。

## オンラインの仕組み（どこが権威を持つか）

| 状態 | 決めるところ | サーバーの検査 |
|---|---|---|
| 自分の車の位置・速度・姿勢・損傷 | その人の画面（操作に遅れを出さない） | 速すぎる移動・建物のすり抜け・カウントダウン中の移動を却下し、元の位置へ戻させる |
| 役（犯人・警察） | サーバー | 人の中からランダムに犯人1人（6人以上なら2人）。残りは警察、空きは CPU の警察 |
| 逮捕・逃げ切り・隠れ家・手配度・無線・修理工場・ヘリの着弾 | サーバー | 受け取った位置と速さで判定（逮捕ゲージ・犯人の大破の瞬間の距離・隠れ家の距離・制限時間）。結果は全員に同じものを配る |
| 壊れた物（ルートが変わる物） | サーバー | 申告した車がその物の近くにいて、壊せる勢いがあるときだけ受け付けて全員へ配る。却下したら申告者の画面で元に戻す |
| CPU の車 | サーバー（同じ物理で動かす） | — |
| 破片・火花・煙 | 各画面（通信しない） | — |

- 送受信: 自分の車を 30回/秒 送り、サーバーが全車を 20回/秒 配る。他の車は 100ms 遅らせて2つのスナップショットの間を補間して描くので、届く間隔がばらついても飛ばない
- 切断: 60秒は席を残す。同じタブで読み込み直すと、サーバーが最後に受け付けた位置から続ける。ホストが10秒戻らなければ次の人がホストになる
- 途中退出: その人は「途中退出」で結果に残る。犯人が全員抜けたら警察の勝ちで終わる
- 不正対策の限界: 改造段数は範囲だけ守る（購入の記録はサーバーに無い）。損傷の値は自己申告。物理を書き換えた画面からの「少し速い」程度の改ざんは検知しきれない

## オンライン対戦の遊び方

```sh
npm install        # 初回だけ（ws）
npm start          # http://localhost:8080
```

1. 同じ Wi-Fi なら、起動した Mac の IP（例 `http://192.168.1.20:8080`）を友達が開く
2. 「オンライン対戦」→「部屋を作る」→ 招待リンクを送る。友達はリンクを開いて名前を入れて「参加」
3. ホストが CPU の警察の数を決めて「スタート」（犯人はランダム）

遠くの友達と遊ぶには、サーバーをインターネットに出す必要がある。どれも必須ではない。

| 方法 | 費用 | 手間 | 注意 |
|---|---|---|---|
| Cloudflare Tunnel（`cloudflared tunnel --url http://localhost:8080`） | 無料 | 自分の Mac で起動し続ける | URL は起動のたびに変わる |
| Render（`render.yaml` 同梱） | 無料プランあり | GitHub をつなぐだけ | 無料プランは使われないと眠り、起きるまで時間がかかる。料金と制限は公式で確認すること（未確認） |
| 任意の VPS / Fly.io / Cloud Run（`Dockerfile` 同梱） | 有料が中心 | Docker で起動 | WebSocket が通ること |

サーバーはデータベースを使わず、部屋はメモリにだけある（再起動で消える）。8人の部屋で、サーバーからの送信はおよそ1人あたり毎秒20回×8台分。

## 素材

- 空（HDRI をトーンマップした画像 20〜55KB。太陽の向きは元の HDR から求めた値）・アスファルト・草地・落ち葉・岩肌・土・コンクリート・杉の樹皮: [Poly Haven](https://polyhaven.com)（CC0。出典表示は不要だが記録として残す）。取得は `sh tools/fetch-assets.sh`
- ビルの外壁（2026-10-26）: Poly Haven（CC0）の Rectangular Facade Tiles（Charlotte Baglioni）・Concrete Panels（Amal Kumar）・Red Brick 03（Rob Tuytel）・Plastered Wall 04（Rob Tuytel）・Corrugated Iron（Jenelle van Heerden, Dimitrios Savva）の色・法線・粗さ（1k、スマホは512）。これに窓・店先（ガラスの店・シャッター・ロビー・日よけのカフェ）・縦看板・屋上広告をコードで描き足して、1枚のアトラス（PC 2048、スマホ 1024）にまとめる（`public/js/facade.js`）。ビル全部で描画は1回。窓はへこみの法線とつやで空を映し、一部の部屋は明かり（発光）が点く。1階は6mごとに違う店になる。ゲームに夜は無いので、明かりは昼でも点いている部屋として見える
- 車: “Car Concept” by Eric Chadwick / Darmstadt Graphics Group（[Khronos glTF Sample Assets](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/CarConcept)、**CC BY 4.0**）。Khronos と 3D Commerce のロゴ（ナンバー・タイヤ側面・部品の発光テクスチャ）を外し、内装の一部を削って面数とテクスチャを減らしたもの（`tools/process-car.mjs`）。PC 用 `car.glb` 8.3万面・3.8MB、スマホ用 `car_lite.glb` 4.6万面・2.4MB。車種ごとに体格を変え、ブルーザーにはバンパーガード、ダートにはウイングを足している。読み込み前と失敗時はコードで作った車（`ProcCar`）で走れる
- 杉の樹冠・草むら・窓と看板の絵・壊せる物: コードで作成（`public/js/trees.js` `scene.js`）
- three.js 本体と後処理（光のにじみ・HDR 読み込み）: MIT（`public/vendor/`）

初回の読み込み（スマホ相当で実測）は約6.4MB。うち車のモデル2.4MBは画面が出てから読む。PC はテクスチャと車が大きい版になる。
